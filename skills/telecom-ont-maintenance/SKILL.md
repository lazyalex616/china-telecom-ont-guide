# 电信光猫维护

先读 [README](../../README.md)，了解用户能看到的教程和提示词。用大白话交流，先说当前能做什么、下一步会改什么，不把整个工作拆成一串让用户猜的协议名。

这里提供步骤和核对线索，不提供万能开关、安装器、设备程序或密码表。读取这个 Skill，不等于用户已经批准登录、改路由器或安装服务。

两台 SSH 的原生应用启动项已经登记，但没有整机或应用环境重启验证。中兴主系统新增命令的临时查找入口也没有完成重启恢复验证。不要把历史结果说成刚刚重新测试过。

型号或固件不同，先重新核对。可以调查，但不要直接执行针对另一型号的工具。

## 先定范围

从用户已有说明和已授权连接资料里确认四件事：设备属于谁、光猫大致型号、现在是谁拨号、这次只查后台还是还要安装 SSH 和补命令。

超密由机主从运营商正规渠道取得。缺少时，用一句话提示联系 10000 号或装维师傅，然后停在凭据之前；不代猜、恢复、提取他人的凭据，也不擅自联系第三方或付款。

给出需要安装的工具、修改的对象和影响，让用户确认。已经批准的同一范围连续做完，不反复索要“继续”；发现需要额外路由配置、其他服务或重启，再单独说明。

不要为了本任务修改拨号模式、默认上网路由、宽带连接、光路注册参数、电视、电话、FTTR、运营商管理服务或防火墙档位。不要刷机、恢复出厂、写固件分区或重挂只读系统。重启需要单独授权，不能为了补验收而自行重启。

凭据从用户认可的密码管理器或临时安全输入读取，不写进仓库、命令参数、脚本、截图或报告。不要打印含密码、Cookie、Token 或私钥的完整对象。客户端私钥留在管理端。

## 第一步：确认去光猫后台的路

先使用已有、明确的管理地址和路径，不扫描网络，也不向猜来的地址提交密码。`192.168.1.1` 只是常见示例，不是所有设备的固定地址。

按现场情况分支：

1. **直接用光猫上网：** 已连接光猫 Wi-Fi 或 LAN 的设备，通常可直接访问管理地址。能通就不改电脑 IP。
2. **光猫拨号，后面接路由器：** 先尝试当前网络的管理访问。打不开再检查地址冲突、访问限制和后级设备模式，不先改桥接。
3. **路由器拨号，光猫桥接：** 查看接光猫的物理侧接口、管理侧地址、去程和回复路径。只增加静态路由不一定足够；可能还需要管理侧地址或限定范围的地址转换。

只读取已知的登录页、状态和现有配置；GET 也可能触发操作，不能当作无副作用证明。

缺少路径时，列出具体目标、接口、改动和保留项，经批准后只改必要部分。不新建或克隆连接来碰运气，不把 PPPoE 接口改成 DHCP，不使用公网或“全部接口”作为临时替代。读回配置，确认既有管理访问和上网配置没有被改坏。

### 用户使用爱快时

先读 [ikuaidev/ikuai-cli](https://github.com/ikuaidev/ikuai-cli) 当前安装和 API 说明，确认设备版本支持。经批准，将 CLI 和配套 Skill 安装到运行 Agent 的管理电脑，不安装到光猫。

显式核对本次目标和凭据来源。CLI 的已保存会话可能优先于环境变量；本地 `auth status` 不等于已经读到了正确路由器。先读取真实设备信息再考虑写入。

使用当前帮助和后端实际接受的字段。预览或命令成功不等于管理路径已通；参数被拒绝时，不放宽成公网入口、通配接口或错误路由。

## 第二步：按 CGI 流程登录

把 CGI 向用户解释成“网页背后接收请求、办事的入口”。它不绕过密码，只是让 Agent 按网页实际流程发请求。

先核对目标身份，再通过已知登录入口提交合法凭据。沿着当前页面引用和跳转读取，不穷举其他型号的接口。

### 中兴样本的登录线索

- 样本的主后台使用 8080 端口 `/login.cgi`，表单字段为 `username`、`psd`。
- 成功后跳转到 `/start.ghtml`，保留服务器下发的 SID 会话。
- 后台内容来自 `/template.gch` 和其中引用的 `/getpage.gch` 页面；子页面可能需要正确来源信息和会话。

这些是已观察固件的线索，先确认当前页面确实使用相同流程，不把端口和路径当作所有中兴光猫的约定。

### ZNXT 样本的登录线索

- 样本入口先经过 80 端口页面，再向 8080 端口 `/login.cgi` 提交后台登录。
- 后台表单字段为 `username`、`psd`，结果包含 `auth_result`。
- 网页 JavaScript 将其中的 `ecntToken` 写入同名 Cookie；只保留 HTTP 的 Set-Cookie 可能不够。
- 后续加载 `/cgi-bin/content.asp` 及其引用的子页面。已核实后可以直接走后台登录段，但仍要处理 JavaScript 设置的会话。

不要把会话占用、锁定、权限不足和密码不匹配混成一个“密码错误”。浏览器能登录而请求失败时，先检查目标、字段、跳转、会话、来源、编码和额外换行，不重复试密码，也不踢掉别人的会话。

登录成功须读到正确型号、固件和当前拨号角色。HTTP 200、302 或一份网页源码都不能单独证明已经进后台；登录页和模板默认值不是设备当前状态。

## 第三步：临时 Telnet，再安装 SSH

### 先拿到合法维护入口

中兴样本使用匹配固件的 `webFac v3` 临时维护认证；方法来源见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。先阅读对应协议和代码范围，不执行参考项目的固化、刷机或导出功能。

ZNXT 样本从已登录后台临时打开 Telnet，再用机主合法取得的命令行凭据登录。需要管理员提权时，使用对应合法凭据。Web 超密、Telnet 密码和提权密码可能不同，缺少任何一个就停止，不猜。

Telnet 不加密，只用于已核实可信的管理链路。记录本次自己临时开启的入口，后面只清理这些，不关闭用户原本的维护服务。

### 检查程序和保存位置

先检查现有 SSH、实际 CPU 架构、位数、字节序、可写空间和当前应用环境。两台样本的程序不能互换；“都是 Linux”不代表二进制兼容。

样本使用从 [Dropbear 上游](https://github.com/mkj/dropbear) 构建的 2026.94 静态程序。获取当前所需版本时核对可信来源、构建方式、许可和完整性，在传输前后比对。不要随便执行论坛附件或来源不明的安装器。哈希一致不等于完成安全审计。

样本已经有 SAF 应用环境，包含自己的进程、根目录、`procd` 和 `rc.common` 启动机制。安装前，从合法主系统维护 shell 核对实际应用管理进程、应用根目录和可写层。进程名 `appmgr` 只是样本线索，不复制旧 PID，也不为此新建容器或停掉应用管理器。

通过正在运行的应用环境写文件，不从外部改它正在使用的叠加文件系统底层。没有经过核实的应用保存和启动机制，就报告缺口，不改只读固件来硬凑。

### 安装并限制访问

经批准，为 SSH 使用独立目录和服务。已有程序、服务、主机密钥或授权公钥列表时先核对，不覆盖，也不默认让所有旧公钥获准访问新增服务。

- 客户端私钥留在管理电脑上，只传批准的公钥；每台光猫单独生成主机身份。
- 私钥和授权公钥文件使用适当权限，通常文件 600、私有目录 700。不要打印主机私钥来核对身份。
- Dropbear 只绑定已核实的内网管理地址；样本用 `-s -g` 禁用密码登录，用 `-j -k` 禁用 TCP 转发，公钥另行限制代理和 X11 转发。
- 不允许空密码，不绑定所有地址来省事，不新增公网 Telnet/SSH 映射。IPv6 和现有映射也要检查，私有 IPv4 监听不等于所有入口都已隔离。
- 使用应用环境已有的原生启动机制，新增自己的启动项，不修改厂商主系统启动脚本、不替换其他服务，不另加外部恢复任务。
- 需要文件传输或内部转送规则时，先说明来源、目标、端口和影响并取得批准，只开本次需要的可信管理路径，用完清理。

从已信任的维护控制台取得主机公钥或指纹，再在管理端核对首次 SSH 身份。不要用关闭主机校验来解决连接失败。客户端算法兼容问题要单独排查，不降级成弱密码或公网入口。

### 验证、收尾

经批准执行实际密钥登录和一个无副作用命令，核对设备身份、权限、程序架构、监听范围和落地环境。

应用环境里的 `root` 不等于主系统 root。检查实际进程和文件视图，明确哪些日志、设备接口可读；不能由 SSH 成功推导出全部主系统访问或日志转发已经完成。

检查程序已保存、自启动已登记和当前运行状态，分别记录。文件存在、启动链接存在或服务当前启动成功，都不是重启恢复验证。

关闭本次临时开启的 Telnet，等服务端连接确实结束，再关闭客户端，并独立确认临时入口已关闭。清理本次传输入口，保留原有服务和规则。清理失败就报告，不宣称已经收尾。

## 第四步：命令缺什么，再补什么

先检查现有 BusyBox、Shell 和用户需要的常用命令。命令找不到可能只是查找路径或当前环境不同，不等于 SSH 登录失败，也不等于必须替换系统。

ZNXT 历史样本已有较齐全的工具，不重复安装。中兴样本补充了可信来源、匹配 AArch64 的 BusyBox 1.37.0，保留了厂商工具；构建来源见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。

需要补充时，先说明缺哪些命令、解决什么问题、存在哪里及启动后的查找方式，经批准再做。核对程序架构和传输完整性，在独立目录保存程序和命令链接，不覆盖 `/bin/busybox`、`/bin/sh` 或同名厂商命令。

先用完整路径调用新增工具，再核对命令查找顺序和符号链接目标。验证代表性的查看文件、处理文字命令即可，不启动新网络服务或改系统配置来证明“工具全了”。

安装 `syslogd`、`logger` 等命令，不等于批准运行或替换现有日志服务。补命令、自启动、日志转发和重启恢复是不同任务。

明确区别程序本身是否保存在持久目录、命令链接是否只是内存文件，以及启动时是否有已核实的恢复机制。不要把应用环境的启动项当成主系统命令查找路径的恢复机制。

## 最后怎么跟用户说

用几句话交代：

1. 现在后台和 SSH 哪些能用，SSH 进入的是哪个环境。
2. 实际改了什么，原来的上网方式是否保留。
3. 新增命令是否可用，本次临时 Telnet 和传输入口是否已清理。
4. 自启动是否已登记，重启恢复是否真的测试，以及仍卡在哪一步。

用已完成的证据说话，不用“应该好了”替代验证。私下诊断可保留普通地址和设备标签，秘密值仍不打印；公开报告、仓库和 Issue 不包含真实账号、设备唯一标识、私人网络地址规划、会话或原始配置。
