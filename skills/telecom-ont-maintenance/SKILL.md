# 电信光猫安全维护

## 先选本次任务

| 用户要做什么 | 先读什么 |
|---|---|
| 登录、浏览器能进脚本不能进、读取模块 | [认证和只读盘点](references/login-and-readonly.md) |
| 比较、删除管理 WAN、调整开关、修时间 | [修改边界与验证](references/change-and-verify.md) |
| 断网排查、整理结果、公开材料 | [证据、报告和脱敏](references/evidence-and-report.md) |

不要一次把所有参考文件加载成执行清单，只读当前分支需要的内容。

## 开箱即可用的材料

- [只读启动提示词](assets/start-readonly.md)：用户第一次交给 Agent 时直接复制。
- [只读模块盘点表](assets/read-only-inventory.md)：需要逐页逐对象读取时使用。
- [变更与独立回读验收表](assets/change-acceptance.md)：获得具体改动授权后使用。
- [断网分层证据表](assets/dropout-evidence.md)：记录同一时段的不同层面证据。

模板只记非敏感字段，不填写真实密码、宽带账号、设备唯一标识或票据。不要自动创建记录文件或上传，先按用户要求选择交付位置。

## 必须满足的前提

1. 用户是设备所有者，或有明确管理授权。
2. 用户已向负责该宽带的装维师傅取得这台设备当前有效超密。
3. 明确知道当前请求从哪个站点、哪台管理设备发出。
4. 知道谁拨号、当前桥接/路由状态和管理路径。
5. 知道本次是只读，还是已明确允许哪些写操作。

缺少有效超密时，不猜、不用默认密码表、不撞登录、不绕锁、不建议刷机解决。

两台不同站点可能都用 `192.168.1.1`。地址相同不能代替身份确认。

## 凭据要求

- 从用户指定的安全存储读取，不写进命令字面量、URL、Skill、报告和 Git。
- 不打印密码、宽带账号、Cookie、Token、配置全文或可供离线猜密的摘要。
- 报告敏感字段只写“存在/不存在、是否一致、是否已安全保存”。
- 无人值守运行配置只有在得到部署授权后才能创建，并限制文件和父目录权限。
- Base64 不算脱敏。

## 默认模式：只读

“能不能”或“看一下”不是改设置授权。

先做：

1. 确认运营商省份、型号、固件、拓扑与正确目标。
2. 复现一次完整、合法的认证流程。
3. 建立当前权限下的菜单和对象清单。
4. 逐模块读取当前状态。
5. 输出事实、差异、未知项和建议。

不提交表单，不开始诊断，不导出整份配置，不重拨，不重启，不清日志，不注销别人会话。

GET 也可能做事，未确认无副作用的入口不访问。

## 不要把登录流程问题说成密码错误

已知密码在浏览器成功时，先查：

- 端口、路径、真实字段名；
- 两段式自动提交；
- JavaScript 写入的 Cookie；
- 同一会话、User-Agent、Referer 和 frame；
- `Locked`、`Logged`、`Privilege`、`Active` 各自的分支。

先证明能读到真正的内容框架和一个模块，不能只看 HTTP 200。

保留仍可安全复用的会话。不会复现时先读当前页面和请求，不反复撞登录。

## 怎样才算盘点完整

逐项覆盖：设备/光路、所有 WAN、管理、LAN/DHCP/IPv6、无线、安全、
NAT/UPnP/DDNS/组播、语音、日志、维护和时间。

每个现有 WAN、SSID、语音线路等都要作为对象核对。页面文件数不是对象覆盖数。

对每项写明：

- 页面和对象；
- 读取结果；
- 当前值依据；
- 下拉项、分页和子页面覆盖；
- 敏感字段是否存在；
- 未覆盖原因；
- 是否发生写操作。

源码默认值不是当前值。追服务端值、加载函数、`selected`/`checked` 和独立重读。

## 写操作的授权边界

先列：目标、当前值、期望值、影响、恢复条件和验证方法。

特别确认：

- 删除的管理连接是否和语音或电视共用；
- 当前选中的是否其实是 INTERNET；
- 是否会改变唯一的远程管理路径；
- 是否要新增网络接口、后台任务或命令入口。

已明确授权的范围内，连续执行到验证完成，不重复要求用户确认同一件事。

只有需要扩大范围、影响新业务、出现未知表单语义或没有可用恢复路径时才暂停。

## 每次只改变目标值

1. 操作前重新读取，不能依赖旧缓存。
2. 核对具体对象和实际内部 ID，不照抄案例 ID。
3. 按当前固件真实提交方式构造请求。
4. 保留其他字段，不擅自统一或归零。
5. 提交一次。
6. 用独立请求回读。
7. 核对业务和安全边界。

不把“成功响应”当成“已生效”。不运行无关压测或未经授权的重启来验收。

## 禁止为了完成任务而扩大操作

- 不改 MAC、LOID、SN、PON 身份或局端注册参数。
- 不刷固件、不恢复出厂、不永久固化命令入口。
- 不关闭整套路由器防护去修一个局部问题。
- 不新建或克隆网络连接配置，除非用户明确批准具体方案。
- 不擅自切换 PPPoE 与 DHCP。
- 不把某省、某型号的 VLAN 和编号复制到另一台。
- 不把“想办法解决”理解为不限范围的授权。
- 不向外部服务上传原始配置、日志、抓包和会话。

## 断网判断

分开：光路/PON、光猫到下游的以太网、后级虚拟化/拨号。

- `PADO` 超时不是光纤故障的专用错误。
- 网口 Up 不证明持续稳定传数据。
- 宽带上网详单不等于 ONU/PON 注册记录。
- ESXi 管理网卡不代表直通给路由器的另一块网卡。
- 路由模式空闲、桥接模式承载流量，不是公平的对照。
- 当前正常光功率不能排除之前的瞬态问题。

没有证据时明确保留假设，不迎合用户预设结论。

## 时间修复

先确认实际时间、时区、原生对时进程和请求，不先猜防火墙。

本地取时成功不等于光猫自己取时成功。

原生方案可用就停止，不额外开启命令入口。原生确实不工作时，先授权替代方案，再部署。

替代方案应当：

- 使用可靠本地时间源；
- 不恢复已删除的运营商管理通道；
- 只修正真实系统时间；
- 临时入口用完关闭；
- 日志不泄露凭据；
- 验证多次定时运行；
- 不因为公网也能访问时间服务而误报安全。

本 Skill 不自动下载或执行任何写设备脚本。

## 最终交付

按 [报告模板](references/evidence-and-report.md) 输出：

1. 已完成和未完成；
2. 修改前、目标、回读结果；
3. 实际运行的验证；
4. 没有运行的验证和仍存在的限制；
5. 敏感信息保存位置的名称，不含值；
6. 真实可能影响用户的业务、安全和恢复边界。

用户应当一眼看懂结果，而不是从几百行源码里自己找结论。
