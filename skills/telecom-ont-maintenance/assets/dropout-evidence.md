# 断网分层证据表

不先认定是光纤、桥接或运营商。记录相同时间窗口，先对齐时区。不要贴宽带账号、设备身份、私人地址或完整原始日志。

## 事件窗口

| 项目 | 记录 |
|---|---|
| 事件时间与时区 | 待填 |
| 相关设备时钟是否准确 | 待确认 |
| 谁在拨号，当时是否有真实流量 | 待确认 |
| 远程通道是否与故障路径共用 | 待确认 |
| 本次允许动作 | 只读，额外动作另行明确授权 |

## 三层证据

| 层面 | 同一窗口的事实 | 来源和覆盖范围 | 能证明什么 | 仍不能排除什么 |
|---|---|---|---|---|
| 光路 / PON | 注册、LOS/LOF、光功率、掉电 | 待填，写单位 | 待填 | 当前正常不排除先前瞬态 |
| 普通网线 / 网口 | Link down/up、速率、错误、接头 | 待填，写实际接口身份 | 待填 | 现在 Up 不等于一直稳定 |
| 虚拟化 / PPPoE | 直通关系、PADO、保活、运行时长 | 待填 | 待填 | 拨号超时不能单独定位光纤 |
| IP / DNS | 管理路径、外网 IP、域名查询 | 待填，不写真实私人目标 | 待填 | ping 不能验证所有业务路径 |

## 推理与下一项验证

1. 已证实事实：待填。
2. 仍存假设：待填，不写成定论。
3. 能区分假设的下一项验证：待填。
4. 是否触发重拨、重启、切模式或新增任务：应为否，除非已有对应明确授权。
5. 新证据推翻了哪个旧说法：如实更正。

不要用“换过光猫”排除两台共用的线、接口、供电和环境，也不要把上网会话详单当成 ONU/PON 注册记录。
