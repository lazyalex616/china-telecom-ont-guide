# 原生应用 SSH：先分清授权、系统边界和验证

## 本参考的用途

用于用户明确询问或授权光猫 SSH、原生应用自启动、密钥登录与重复管理地址处理时。不是读完就执行的安装清单，也不替 Agent 提供登录权限。

本 Skill 包只含方法，不含 SSH 程序或自动部署器。完整工具包和仓库的第 12 章另有构建说明及 `tools/ont-ssh.init` 模板；独立复制 Skill 时不依赖仓库外的相对路径。

## 先核对本次是否允许写入

必须具备本人或明确授权设备、装维提供的当前有效超密，以及已核实的站点和管理路径。

- “怎样连上的”“能不能开 SSH”只解释，不修改。
- 只读盘点不授权开启 Telnet、进入维护模式、传文件或安装程序。
- 安装服务、写公钥、生成主机身份、注册自启动、修改路由器、实际认证验证分别列入方案。
- 重启光猫或应用环境需要单独对应授权，不能当作默认验收。
- 已有服务或用户文件先核对，不能把它们当成需要重建的半成品。

## 方法顺序

1. 在合法维护路径中核对设备、权限、CPU、位数、字节序、当前工具和已存在的服务。
2. 核对已有 SAF 应用管理进程、它的根目录、启动机制、可写持久层及与主系统的关系。
3. 获得安装方案授权后，才通过已授权主系统 root 通道进入这个现有环境。
4. 使用可信上游、自行审核构建的对应架构程序，传输前后比对完整性。
5. 只在批准的新目录安装，公钥、主机身份和权限独立核对，不覆盖未知现有文件。
6. 限定管理地址、密钥认证和转发功能，注册原生应用启动项，不改主系统固件或应用管理器。
7. 核对路由器去程和回程、管理入口及已有外部映射，再通过可信主机身份实际登录验证。
8. 清理自己临时打开的 Telnet 和传输规则，独立确认 SSH 仍可用，准确报告未验证范围。

不是每台设备都有 SAF。没有当前设备证据就停止，不猜 PID、目录、接口或固件功能。

## 应用 root 不是主系统 root

样本通过 `nsenter` 进入已存在的应用环境。必须从当前主系统核实 PID 与根目录，不复用旧 PID；不能把管理电脑或已经登录的应用 shell 当作主系统。

样本共享网络等资源，但进程和挂载目录视图不同。应用 SSH 的 UID 0 和 `/sbin/procd` 不证明可以管理主系统进程、访问全部厂商日志或修复主系统启动。

应用内文件通过运行中的应用环境写入，不从外面修改正在使用的叠加文件系统底层目录。这是防止两套视图不一致，不是给任意目录写入的许可。

## 服务与密钥边界

- 示例程序位置 `/opt/ontssh/dropbearmulti`，主机身份 `/opt/ontssh/hostkey`，公钥授权 `/root/.ssh/authorized_keys`。
- `.ssh` 和服务目录 700，主机私钥、公钥授权文件 600；这些通用路径不是现有文件可被覆盖的证据。
- 客户端私钥保留管理端安全存储，只传公钥；每台光猫在设备本地生成独立主机身份。
- 禁止密码和空密码认证，不为解释问题提供默认口令表。
- 样本参数 `-s -g -j -k -I 600 -K 30`，公钥使用 `no-agent-forwarding,no-port-forwarding,no-X11-forwarding`。
- 地址必须现场核实，不使用通配监听，不因为绑定私有 IPv4 就省略可达性和 IPv6 检查。
- 自启动只启动自己的服务，有限重试，不重启光猫或现有框架，不启用未知启动分支。
- PID 文件核对执行程序后才可用来停止本服务，不用全局 `killall` 停 SSH。

## 两个站点管理地址一样时

同为 `192.168.1.1` 只是一种常见示例，不保证是当前设备地址。

分别使用本站点路由器的独立内网入口，经目标地址转换转送到本站点光猫 SSH；必要时把来源转换为光猫管理网段中的已确认地址，保证回程。

规则要限制内网入口、管理出口、协议、端口和批准的来源。普通端口映射不接受内网接口时，应检查高级 NAT 能否表达方案，不能改成公网接口或全部接口凑成功。保留现有规则，使用回读得到的 ID，不新增或克隆网络连接配置。

本参考不提供固定真实站点地址、接口或路由器 Token，不自动调用写接口。

## 主机身份与客户端兼容

从原有可信控制台读取主机公钥和指纹，本地核对后加入专用 `known_hosts`。非默认端口使用 `[地址]:端口`，不关掉严格主机检查，也不把 `ssh-keyscan` 单独当可信身份来源。

样本中 Windows OpenSSH 9.5 的扫描器出现 `choose_kex: unsupported KEX method`。正式连接固定 `KexAlgorithms=curve25519-sha256`，保留密钥验证后成功。这只是特定组合的兼容记录，不是放宽安全策略的通用理由。

## 验收和交付

分别记录：

1. 当前是否实际认证并执行命令，架构和目标身份是否一致。
2. 登录处于应用还是主系统，实际看见的 PID 1 是什么。
3. 监听地址、版本、禁密码和禁转发参数、公钥授权和文件权限。
4. 启动项、链接和落盘证据，与真正重启验证分开。
5. 自己的临时入口是否关闭，已有转发是否保留，是否新增外部可达路径。
6. 未完成的主系统命令恢复、日志转发、重启恢复等独立任务。

等待自己开启的临时 Telnet 服务结束连接后再关闭客户端，并回读状态，不能立即断开后假定清理完成。保护别人原有维护会话。

应用 BusyBox 可能没有 `stat` 等命令，使用已核实存在的工具。远程命令退出非零不是连接路径失效的证明，不因此自动换到公网。

公开报告不包含真实入口、站点、接口编号、主机公钥/指纹、私钥、凭据、原始输出或私人注册表。仅保留授权公开的省份、型号、固件、通用文件路径、方法和验证边界。
