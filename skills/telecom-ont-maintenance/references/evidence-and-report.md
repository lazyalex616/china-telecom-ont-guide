# 证据、报告与脱敏

## 断网不要先选边站

区分光路、以太网、后级虚拟化和拨号。

| 证据 | 不能直接推出的结论 |
|---|---|
| PADO 超时 | 肯定是光纤坏了 |
| 网口 Up | 网线和网口已完全排除 |
| 宽带上网详单 | ONU/PON 光路一定掉线 |
| ESXi 管理网卡正常 | 直通给 iKuai 的另一块网卡也正常 |
| 换了光猫仍然有问题 | 两台设备共用的线、接口和电源都正常 |
| 路由模式几乎无流量但稳定 | 桥接模式是唯一原因 |
| 某次光功率正常 | 整段时间不存在瞬态故障 |
| 光猫 HTTP Date 看着像开机秒数 | 它永远是运行时长而不是系统时钟 |

要求相同时间窗口、准确时区、明确接口身份和统计口径。

## 报告模板

```text
结果：已完成哪些，哪些没完成。

范围：目标设备/模块，本次实际授权。

覆盖：读了哪些页面、现有对象、子页和分页；哪些没读到，为什么。

变更：
- 对象：
- 修改前：
- 目标：
- 提交结果：
- 独立回读：
- 业务/安全验证：

证据：实际时间、状态、错误码和字段，不含凭据。

限制：哪些是推断，哪些验证未运行，临时入口是否确认关闭。

敏感信息：只写已存入用户指定安全存储，不写值或摘要。
```

## 好的措辞

- “当前捕获窗口内，此接口和过滤条件下没有看到请求；另有进程状态支持客户端未启动。”
- “页面选项从 high 变为 low，独立重读保持一致，其他控制字段未变。”
- “真实系统时间已正确；原生 NTP 同步标志仍不能作为成功依据。”
- “只有静态校验，未在该读者设备上运行。”

## 不好的措辞

- “200 就是登录成功。”
- “我抓了很多页面，所以全部读完。”
- “网线通电，肯定是电信问题。”
- “删管理之后电信永远改不了任何配置。”
- “脚本能解析，所以全型号可用。”
- “没验证，但应该没问题。”

## 公开前移除

密码、宽带账号、语音号码、LOID、SN、MAC、SSID/BSSID、真实公网地址、
私人域名、详细地点、Cookie、Token、授权头、完整请求、配置导出和原始抓包。

短密码的摘要和 Base64 不是安全的公开替代物。

不要把真实数据放在示例、截图、附件、文件名、Git 作者信息或旧提交里。

示意输出重新编写并标注示意，不冒充原始实测。

## 附件与外部服务

不自动上传真实配置、HAR、pcap 或截图给第三方。

确有必要分享时，先取得明确授权，再逐项审阅。拿不准是否脱敏就不分享原件。

## 结论被推翻时

明确撤回旧说法，写清新证据改变了哪一项判断。

不要为了维护前一个结论，把仍未确认的原因继续写成事实。
