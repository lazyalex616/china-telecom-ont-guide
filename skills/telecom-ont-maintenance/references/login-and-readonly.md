# 认证与只读盘点

## 使用前提

已确认本人或授权设备，并已从装维师傅取得当前有效超密。没有则停止，不做凭据恢复或猜测。

## 两个案例的认证线索

这些只是已观察样本，不是所有固件的保证。

### 浙江 ZNXT ZN-XG120

浏览器流程：

1. 80 端口 LuCI 页面先提交 `username=useradmin` 和 `psd`。
2. 返回页再自动向 8080 `/login.cgi` 提交 `username=telecomadmin` 和 `psd`。
3. 返回页含 `auth_result`。
4. 网页 JS 将 `auth_result.ecntToken` 写入 `ecntToken` Cookie。
5. 加载 `/cgi-bin/content.asp` 及框架内子页。

已知流程后可直接走第二段，但仍须复制 JavaScript 设置的 Cookie。

`Locked`、`Logged`、`Privilege`、`Active` 不能混为一个成功/失败布尔值。
`Logged=1, Privilege=0` 可能是会话占用，不等于密码错。

### 上海中兴 ZXHN G7615V2

样本使用 8080 `/login.cgi`，字段 `username` 和 `psd`。
成功后 302 到 `/start.ghtml` 并下发 SID。
内容在 `start.ghtml` / `template.gch` 和 `getpage.gch` 页面集合中。

子页需要正确会话和框架来源，不穷举其他机型的路径。

## 登录失败的检查顺序

1. 目标站点与设备身份；
2. 本机请求是否真正发出；
3. 端口、路径、表单字段；
4. 自动提交和跳转；
5. JS Cookie、User-Agent、Referer、frame；
6. 会话占用、锁定和权限；
7. 编码、额外换行或 BOM；
8. 最后才在证据充分时判断凭据不匹配。

不打印真实值或摘要。比较只输出是否一致。

## 只读清单怎么建立

从当前菜单、frame、页面映射、已引用子页、现有下拉对象和分页扩展。

安全入口必须已知是状态或设置展示，不是根据 GET 方法猜安全。

排除未授权动作：保存、删除、注销、重启、恢复、升级、注册、开始诊断、清日志、导出、镜像和抓包。

## 每类模块至少看什么

| 类别 | 读取内容 |
|---|---|
| 设备和光路 | 型号、固件、能力、状态、功率单位、运行时长、告警 |
| WAN | 每条连接的业务、模式、VLAN、绑定、状态和当前对象编号 |
| 管理 | 管理 WAN、服务启用、上报/注册状态及共用业务 |
| LAN/IPv6 | 管理地址、池、DNS、租期、RA/DHCPv6、绑定 |
| 无线 | 硬件能力、每个现有 SSID、配置开关与实际无线电状态 |
| 安全 | 实际档位、总开关、独立防护、过滤和访问控制 |
| 应用 | NAT、UPnP、DDNS、DMZ、组播、VPN、STUN |
| 语音 | 启用、注册、错误原因和业务依赖 |
| 日志/维护 | 当前开关和策略，不触发动作 |
| 时间 | 真实时间、时区、服务器、接口、状态和后续运行 |

## 什么不算读完

- HTTP 200，但内容是登录页；
- 抓到网页文件，但未解析动态对象；
- 只看默认选中的一条 WAN；
- 只读某个 SSID，却声称无线模块全部读完；
- 看到模板，就认为硬件一定存在；
- 返回 302，就认定模块不存在；
- 用页面数量代替覆盖清单。

不能读取的明确标记，不能用猜测填表。
