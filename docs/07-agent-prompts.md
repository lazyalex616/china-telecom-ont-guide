# 07：可以直接复制给 Agent 的提示词

[返回首页](../README.md)

## 用法

先选你当前要做的一段，不要一股脑把全部提示词当成已经授权的操作清单。

所有提示词的前提都是：**本人或明确授权设备，且已向装维师傅取得当前有效超密。**

涉及密码的实际值，通过你自己的安全凭据工具提供。不要把本页提示词连同真实密码发到公开讨论区。

## 提示词 1：建立边界，先不要动设备

```text
我要维护本人或已获明确授权的电信光猫。
我已经/准备向负责这条宽带的装维师傅取得当前有效超级管理员账号和密码。
如果还没有有效超密，请停在只读准备，不猜密码、不绕锁、不刷机。

先整理：运营商省份、光猫型号/固件、谁在拨号、管理地址、网络拓扑、
现有远程管理路径、是否在用固定电话和运营商电视。

不要提交任何设置，不新增网络配置，不改默认网关，不重启。
密码只从我指定的安全存储读取，不写进命令、日志、Skill 或代码仓库。
先告诉我缺哪些前提，以及接下来只读检查的具体范围。
```

## 提示词 2：浏览器能登录，脚本失败

```text
同一份超密已经在目标光猫浏览器页面登录成功。
脚本失败时，请优先检查完整认证流程，而不是怀疑密码。

先读当前登录表单、提交前 JS、返回页自动提交、Cookie 和 frame 关系。
核对端口、路径、username/psd/password 等真实字段名。
注意 ecntToken 可能由 JavaScript 写入，不在 Set-Cookie 里。
保留相同的浏览器标识和必要来源信息，优先复用已授权会话。

分别解释 Locked、Logged、Privilege、Active，不能把已有会话说成密码错。
不要反复提交导致锁定，不要更换密码或使用默认口令表。
不要打印密码、Cookie、Token、登录请求正文或完整响应。

验收：读到真正的内容框架和一个确定存在的模块，而不是只看 HTTP 200。
```

## 提示词 3：每个页面、每个模块都只读盘点

```text
这次只允许盘点，不允许修改。

从当前权限可见菜单、frame、页面映射、子页面、现有下拉对象和分页建立清单。
不通过猜文件名盲扫，也不访问重启、恢复、注销、开始诊断、导出等动作端点。
GET 不自动等于安全；不能确认副作用的入口先跳过并写原因。

逐项覆盖：设备与光路、所有 WAN、远程管理、LAN/DHCP/IPv6、无线、
安全、NAT/UPnP/DDNS/组播、语音、日志、维护和时间。
每条 WAN、每个已有 SSID、每条语音线路等都要单独读取。

输出覆盖表：模块、页面、当前对象、分页/下拉覆盖、读取结果、
值的依据、敏感字段是否存在、未覆盖原因、是否发生写操作。
不要把源码默认变量当成当前值，要追 selected/checked 和加载逻辑。
遇到 302，先核对会话和框架，不直接说没有功能。
不要因抓到了多少页就宣称穷尽全部配置。
```

## 提示词 4：对比两台光猫，但不要对齐业务参数

```text
请分别通过两个站点已有的授权管理通道读取光猫。
两台可能同为 192.168.1.1，必须先确认请求来自哪边以及设备身份。

按语义对比：上网模式、所有业务 WAN、端口绑定、远程管理状态、
语音/电视依赖、QoS、UPnP、防火墙、LAN/IPv6、时间和日志。

不要逐字比较整份 HTML 后把框架噪声当成配置差异。
不要复制 VLAN、MAC、LOID、SN、连接编号或接口名。
不同厂商的数字枚举不能直接对齐。
桥接不代表账号密码字段已清空；如授权读取，只存安全存储，不回显。

输出：已证实的差异、可能影响、不能直接比较的项、尚未读取的项。
这次不执行任何修改。
```

## 提示词 5：删除一条明确的管理连接

```text
我准备删除光猫的一条运营商 IP 远程管理 WAN，但还没有授权实际删除。

先只读列出所有 WAN 的名称、业务类型、模式、VLAN、启用状态、
端口绑定和内部索引，辨认哪条是真正目标。
核对是否与语音、电视或其他业务共用，说明删除会失去什么。
确认当前远程操作不是依赖这条唯一通道。

不要照抄教程里的索引 0 或任何 VLAN，不要删除默认选中的 INTERNET。
读当前页面删除按钮真实提交逻辑，展示不含密码/票据的目标摘要。
我确认目标和影响以后，你再执行。

执行后独立重读列表，确认只删除目标，保留业务仍在，后级拨号和外网正常。
不要承诺删 TR069 等于永久屏蔽所有运营商管理，不动光路注册身份。
```

## 提示词 6：授权一组明确改动，并连续完成

```text
以下项目已经获得授权：
1. 在指定光猫上将已确认的目标开关改为我指定的状态。
2. 其他设置原样保留。

开始前重新读取当前值。每项执行前核对对象，每项执行后独立回读。
保持拨号、桥接、VLAN、LAN、光路身份和现有远程路径不变。
如涉及删除合并业务的 WAN，必须已有对该业务影响的明确授权。

在以上授权范围内连续做完，不重复询问同一件事，不中途交半成品后停下。
如发现需要扩大范围、会影响新的业务、或没有可用恢复路径，才暂停说明。

不要运行额外压测、重启或新开浏览器来冒充验收。
最终给我：修改前、目标、回读结果、实际完成的验证、仍存在的限制。
```

使用时把第 1 项替换为真正具体的内容，例如“只把光猫防火墙从高档改为低档，独立开关和 iKuai 防护不动”。不要保留含糊的“优化全部设置”。

## 提示词 7：修复桥接光猫的时间

```text
目标是让光猫实际系统时间正确，并且后续可以自动维护。
先不要改设置。

先读真实时间、时区、对时开关、服务器、接口选择和 WAN 模式。
确认本地可靠时间源准确，区分管理设备能取时和光猫本身能取时。
如果保存 NTP 地址后仍失败，先看进程和已授权范围内的请求证据，
区分没发请求、被拦截、时间源无效和固件不支持本地接口。

不要把 iKuai 的 listenport 当 NTP 监听字段。
若启用本地 NTP 服务，验证并限制公网访问，保留上游回应和内网取时。

原生对时能用就不增加命令访问；确实不能用时，提出本地自动校准方案。
额外方案必须说明凭据、权限、临时入口、关闭方法、调度、日志上限和失败处理。
不恢复 TR069，不新建 WAN，不改 MAC、LOID、SN，不刷机、不固化 Telnet。

获得具体方案授权后再执行。
验收真实光猫时钟和多次定时运行，不只看“设置成功”或“同步状态”。
不要为了验证而把设备设回 1970 年，或擅自重启。
```

## 提示词 8：排查断网，不预设是谁的问题

```text
请只读排查这次断网，不预设是运营商、桥接、光纤、光猫或网线。

先分开三层：光路/PON、光猫到小主机的以太网、后级虚拟化/拨号。
确认 iKuai 的外网卡是否直通，ESXi 管理网卡记录不能代替它。
读取相同时段的运行时长、接口 down/up、速率/错误计数和拨号记录。

PADO 超时不直接证明光纤故障，Link Up 不排除数据链路不稳定。
运营商的宽带账号会话记录不等于 ONU/PON 注册记录。
路由/桥接对比必须明确是谁拨号、有无真实业务、是否在相近负载下比较。

输出：事实、不能证明什么、仍可能的原因、下一项能区分原因的验证。
证据不够就写不够，不为了迎合我而把推测写成定论。
不重拨、不重启、不切模式、不新增连接配置。
```

## 提示词 9：把结果整理成别人能看懂的报告

```text
请用大白话写一份报告，不堆网页源码或术语。

先写实测结果；再写依据、范围和限制。
每个修改都要有提交前值、目标值和独立回读结果。
未运行的验证明确写未运行，不把静态检查说成真实设备测试。

隐藏所有密码、完整账号、LOID、SN、MAC、公网地址、私人域名、
手机号、Cookie、Token、请求正文和凭据摘要。
示例输出重新编写并标注示意，不直接粘原始日志。

如果结论被新证据推翻，明确撤回旧说法，不继续替旧说法找理由。
```

## 提示词 10：准备公开发布

```text
我要公开发布一份脱敏教程，但现在先不要上传。

从干净的新目录整理公开材料，不直接推私有基础设施仓库。
只保留经确认可公开的运营商省份、型号、固件系列和必要协议字段。
所有真实凭据、设备唯一标识、站点名称、私人地址和会话资料都移除。

检查工作区、暂存区、首次提交历史、提交作者邮箱及所有附件。
不要把 Base64 当脱敏，不发布弱密码的可离线比对摘要。
保留引用来源、许可证和“样本适用范围/未验证范围”。

先完成静态检查和逐文件审阅，再按我明确授权的仓库和可见性发布。
发布后重新读取远端，确认公开状态、文件内容和本地提交一致。
不要擅自发布原始配置、HAR、抓包或设备截图。
```

## 一个很有用的总约束

可以加在任何一段后面：

> 你要帮我完成目标，但不能靠猜测、扩大授权或隐藏失败来完成。正确性优先于“看起来已经完成”。
