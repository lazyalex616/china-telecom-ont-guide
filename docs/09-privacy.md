# 09：公开发教程、日志和 Issue 之前，怎样脱敏

[返回首页](../README.md)

## 一、先说最省事也最可靠的办法

**不要上传原始配置和原始会话。**

自己重写一份只保留必要信息的文字示例，通常比给几百 KB 原始文件做脱敏更可靠。

尤其是光猫配置：你只想讨论一个 QoS 开关，整份配置里却可能同时有宽带密码、语音密码、Web 超密、设备身份和运营商平台凭据。

## 二、逐类检查

| 数据 | 怎样处理 |
|---|---|
| 超级管理员密码 | 整个移除，不留前后几位 |
| 宽带账号和密码 | 整个移除，账号本身也可能包含电话或地域信息 |
| Telnet 和提权密码 | 整个移除，不因为它“只是默认值”就忽略 |
| Wi-Fi 密码 | 整个移除 |
| SSID / BSSID | 自定义名字和实际地址移除，用示意名称 |
| 语音账号、号码和密码 | 移除 |
| LOID、SN、PON/ONU 标识 | 移除，不只遮一小段 |
| MAC | 实际地址移除；不要把网上通用示例当成自己的值公开 |
| 公网地址和个人域名 | 用文档保留地址和通用占位符替代 |
| 家庭站点名、详细住址 | 移除，只保留已同意公开的省份等必要范围 |
| Cookie / SID / ecntToken | 整个移除 |
| `_SESSION_TOKEN` 等页面票据 | 整个移除 |
| Authorization、API Token | 整个移除 |
| 配置导出、HAR、抓包 | 默认不公开，除非已经逐项审阅并明确授权 |
| Git 提交邮箱和本机路径 | 也要检查，不只看文章正文 |

## 三、下面这些不叫脱敏

### Base64

Base64 只是换一种写法，能直接还原。

不要把密码 Base64 一下，再说“已经加密可以公开”。

### 短密码的摘要

摘要不是给别人看的保险箱。短密码可以被离线枚举比较。

如果只是检查两端值是否一致，自己在内存里比完，报告 `matches=True/False` 就够了。不要发摘要前几位、完整摘要或可供验证候选密码的信息。

### HTML 的密码输入框

页面上显示成星号，不代表源代码、返回数据或提交正文里也是星号。

```html
<input type="password" value="REDACTED">
```

这里的 `type=password` 只是显示方式。真实 `value` 如果是明文，源码里照样能看到。

### 删除文件后再提交

如果敏感文件已经进过历史，后来删掉不代表历史中也没了。

这份教程采用的是新建干净工作区，只选择审阅过的公开文件提交，避免把私有运维仓库的旧历史带出来。

## 四、截图特别容易漏什么

- 地址栏里的票据和私人域名；
- 页面右上角账号或宽带号码；
- 表格下方没留意的 SN、MAC、LOID；
- 浏览器其他标签和收藏栏；
- 密码管理器弹层；
- 装维后台的用户地址、电话和业务编号；
- 图片文件名和元数据。

打码要覆盖真实像素，不能只是加一个可移除的标注层。拿不准时，**不要发原图，重新画一个示意图或重写文字**。

## 五、示例地址怎么选

公网示例使用文档保留网段，例如：

```text
192.0.2.10
198.51.100.10
203.0.113.10
```

这些不是让你真的去测的目标。

`192.168.1.1` 这类管理地址本身很常见，可以作为教程示例，但必须说明不能代替现场确认。不要把自己的整张地址规划表原样贴出来。

私有 DNS 后缀、内网服务名字、主机名和隧道名，也可能透露真实环境，没必要就删。

## 六、密码应该放哪里

优先使用密码管理器或安全凭据库。

无人值守任务如果必须有本地运行配置：

- 只放在执行它的设备上；
- 文件只允许必要的账户读取；
- 例如 Linux 下模式 600，父目录也要有合适权限；
- 不放在 Web 服务目录；
- 不放在 Git 工作区；
- 不把内容打印进日志；
- 不自动上传、分享或导出。

`SKILL.md` 里应写“从用户指定安全存储读取”，而不是写真实密码。

本仓库的 `.example.json` 只能是占位模板。真实 `.local.json` 不应该被提交。

## 七、Git 发布前至少做这些检查

先在本地看：

```sh
git status --short
git diff --cached --stat
git diff --cached --check
git diff --cached
```

逐个文件确认：

1. 只有你打算公开的文档、示例和代码；
2. 没有原始配置、HTML 会话、HAR、pcap 或私密 JSON；
3. 没有真实密码、账号、票据和设备身份；
4. 没有私人域名、真实公网地址和住址；
5. 提交作者邮箱符合你的隐私选择；
6. 新建公开仓库没有混入旧私有历史；
7. 示例日志明确标成示意，不冒充原始实测输出。

运行仓库的静态检查：

```sh
python3 tools/check-repository.py
```

这个检查能发现一部分常见问题，**不能替代人工逐文件审阅，也不能保证穷尽所有秘密**。

不要在公开 Issue 中粘贴检查器命中的真实值。最好只报告文件、类别和行号。

## 八、发布后再核对一次

- 仓库是否确实是你打算的公开/私有状态；
- 远端提交是否与你审查过的一致；
- README 和所有章节是否能打开；
- 示例文件是否仍然只是占位符；
- 没有把运行配置补传上去；
- 没有把“只做了静态检查”改写成“全型号实测通过”。

如果不能确认某份材料已经安全脱敏，就不发布它。公开内容少一点，远比公开一份带密码的原始配置好。
