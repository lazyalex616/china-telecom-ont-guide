# 03：怎样把每个页面、每个模块读清楚，而不是只数网页个数

[返回首页](../README.md)

## 一、先定义“读完”是什么意思

下面几件事不是一回事：

1. 找到一个页面地址；
2. HTTP 返回 200；
3. 返回的确实是该模块，不是登录页；
4. 看到了页面源码；
5. 读懂了当前显示值；
6. 切换过该模块里所有现有配置对象；
7. 核对过子页面、分页、下拉项和当前权限范围。

**做到第 4 项，不能宣称已经做到第 7 项。**

本次样本里，上海中兴发现并读取过 85 个页面文件；浙江菜单发现 42 个入口，其中 40 个有模块内容，2 个当时返回跳转。但这些数字不证明所有动态对象和隐藏状态都被穷尽，也不证明那两个入口一定“没有功能”。

教程要求的是：**列清覆盖范围，没读到的就标记没读到。**

## 二、先建页面清单

页面清单可以来自：

- 当前登录用户实际看到的菜单；
- 页面的 frame；
- 菜单 JavaScript 中的页面映射；
- 当前模块明确引用的子页面；
- 下拉框里的现有 WAN、SSID、语音线路等对象；
- 分页和分类标签。

### 浙江样本的线索

菜单由 `/JS/menu.js` 一类脚本提供，模块页面位于 `/cgi-bin/` 下。

示例类别：

```text
状态：设备、网络侧、用户侧、语音、远程管理、智能应用
网络：宽带、绑定、LAN、无线、远程管理、时间、路由、QoS
安全：防火墙、MAC 过滤、端口过滤、访问控制
应用：DDNS、NAT、UPnP、语音、组播、VPN、STUN
管理：账号、设备管理、日志、维护
诊断：网络诊断、语音诊断
```

### 上海样本的线索

中兴模板里会出现菜单映射，例如：

```text
某一级菜单 -> 某模块.gch
某模块 -> 另一个子模块.gch
```

看到下一级页面后可以继续扩展清单，直到本轮没有新入口。但**不能只靠文件名猜出几十个地址然后盲扫**。

## 三、先把危险入口从自动读取里拿掉

以下名称或动作要特别谨慎：

- 重启；
- 恢复、恢复出厂；
- 升级、上传固件；
- 重新注册、下发业务；
- 注销登录；
- 开始诊断、语音仿真；
- 清日志；
- 保存、提交、应用；
- 导出、备份、配置下载；
- 开启 Telnet、抓包、端口镜像。

有些“页面”只是展示表单，有些 URL 一打开就做事。必须先读调用逻辑或使用厂商说明，分清两者。

安全做法是：

> 可以读取设置页当前状态，但不点击动作按钮，不调用动作 CGI，不提交表单。不能确认无副作用的入口，先标为“未读取：需要确认动作性质”。

整份配置、HAR、抓包也不要自动导出。它们经常带着很多你本来没想收集的密码。

## 四、清单里应该有哪几列

| 字段 | 记录什么 |
|---|---|
| 一级/二级模块 | 例如“网络 / 时间管理” |
| 页面路径 | 去掉登录票据后的路径 |
| 当前用户是否可见 | 可见 / 菜单未展示 / 不确定 |
| 读取结果 | 成功 / 登录页 / 跳转 / 无权限 / 无法确认 |
| 当前对象 | 第几条 WAN、哪个 SSID、哪条语音线路 |
| 下拉项或分页覆盖 | 已读哪些、还剩哪些 |
| 当前值的依据 | 页面选项、服务端返回、动态接口、进程或日志 |
| 敏感字段 | 只记“存在”，不记原值 |
| 未覆盖原因 | 诚实写清楚 |
| 是否发生写操作 | 只读阶段必须是“否” |

示例报告见 [examples/read-only-report.example.md](../examples/read-only-report.example.md)。

## 五、按这张表逐类核对

### 1. 设备和光路状态

读取：

- 型号、硬件版本、固件版本；
- 上行制式；
- 真实运行时长；
- 光路注册状态；
- 光功率、温度和告警；
- LAN 口协商和连接状态。

报告中不要出现真实 SN、LOID、MAC 和设备识别码。状态计数要带采样时间和单位，不能把某一时刻正常写成“一直正常”。

### 2. 全部 WAN 连接

每一条现有连接都要单独看：

- 名称和业务类型；
- 启用状态；
- Route 还是 Bridge；
- VLAN 和优先级；
- IPv4 / IPv6；
- 绑定哪些物理端口；
- DHCP、静态地址、PPPoE 或桥接类型；
- NAT、组播相关选项；
- 是否有拨号账号、密码残留字段。

只看下拉框默认选中的第一条或“上网”那条，不叫读完全部 WAN。

### 3. 远程管理

核对：

- 是否有 TR069、ITMS、ACS、CWMP 相关 WAN；
- 这些名称是不是同一个管理功能的不同叫法；
- 是否和语音或其他业务共用；
- 管理服务是否启用；
- 注册或上报状态；
- 页面是否还有服务器地址、周期上报、连接请求端口；
- 是否存在另一个手机管理、插件或其他管理模块。

服务器地址本身也可能包含账号、票据或私人域名，不要不经检查直接公开。

### 4. LAN、DHCP 和 IPv6

看管理地址、掩码、地址池、租期、DNS、RA、DHCPv6、端口绑定等。

读到不认识的默认值，先记录，不要为了“统一”改它。

### 5. 无线

按频段和每个现有 SSID 分开看：

- 硬件是否真的有无线模块；
- 配置启用和无线电实际状态是否一致；
- 加密方式；
- 信道、带宽；
- 隔离和 WPS 等选项。

没有无线硬件的设备也可能带着一整套通用无线网页。**页面里有模板，不代表硬件有这个功能。**

### 6. 安全

看防火墙档位、总开关、独立攻击防护、IPv6 状态、访问控制、MAC/IP/端口/URL 过滤。

不能把“防火墙低档”自动等同于“全部独立开关都关了”。

### 7. 应用

看 UPnP、DDNS、DMZ、端口映射、组播、VPN、STUN 等。

“没有规则”和“功能关闭”分别记录。例如，UPnP 开着但当前映射表为空，不等于 UPnP 已关闭。

### 8. 语音

看线路是否启用、是否注册、协议、错误原因及相关绑定。

语音密码不要回显；当前注册失败也不等于用户永远不用固定电话。

### 9. 管理、日志和维护

看账号角色、日志是否启用、日志级别、远程日志状态、升级策略等。

不要为了读出“当前设置”去点“恢复默认”“清空日志”“上传固件”。

### 10. 时间

分别记录：

- 当前真实时间；
- 时区；
- 对时开关；
- 时间服务器；
- 所选业务接口；
- 同步状态；
- 后续是否持续运行。

时间服务器地址和同步成功状态必须分开，详见 [05](05-time-sync.md)。

## 六、源码里最容易认错的几种值

### 默认值

脚本里写：

```javascript
var level = 1;
```

这只能说明这里出现过一个变量。你还不知道它是默认值、初始化条件、权限标志，还是当前设置。

### 当前选中值

HTML 里可能是：

```html
<option value="low">低</option>
<option value="high" selected>高</option>
```

它明确说明此处的选项是高。但还要看页面加载脚本会不会继续改写选项。

### 隐藏字段

一个隐藏字段和勾选框不同步，不能马上说“隐藏字段一定是错的”或“勾选框一定是错的”。

应当追：

1. 服务端生成了什么；
2. 加载函数做了什么；
3. 用户改动后，提交函数重写了什么；
4. 保存后独立重读是什么。

浙江样本的 QoS 页面就出现过隐藏字段和实际勾选状态不一致。案例验证的是配置勾选状态改变，不应顺便宣称“所有硬件转发路径的 QoS 都已通过压测证明消失”。

## 七、跨站点对比怎么做

不要把两份几百 KB 的 HTML 直接逐字 diff，然后把上千处框架差异都当配置差异。

先按同一套语义整理：

| 语义 | 上海样本 | 浙江样本 | 是否允许直接对齐 |
|---|---|---|---|
| 上网方式 | 桥接 | 桥接 | 可以比较，但保留各自业务参数 |
| 管理 WAN | 已无专用条目 | 原有管理加语音条目 | 必须确认用户是否使用语音 |
| 上网 VLAN | 按现场值 | 样本为 41 | 不能照抄 |
| 其他业务 VLAN | 样本为 85 | 样本为 43 | 不能照抄，业务含义也要核对 |
| 防火墙档位 | 某厂商数值 | 另一个厂商字符串 | 看标签，不直接比数字 |
| Wi-Fi | 有硬件但当时关闭 | 无无线模块 | 不能“对齐”为同样硬件 |
| NTP 是否真同步 | 初始没有 | 初始没有 | 需要单独修复并验证 |

## 八、读完以后给用户什么

推荐交付三份内容：

1. **覆盖清单**：哪些模块读了，哪些没读到，为什么。
2. **语义差异表**：不是堆源码，而是每个差异会影响什么。
3. **修改建议和影响**：建议不是授权，不能读完顺手全改。

敏感字段只说“存在，已存入你指定的安全存储”，不把它们粘进报告。

尤其记住：**光猫桥接，不保证旧拨号账号和密码字段已经清空。** 案例里就读到过残留字段。实际正在使用哪个账号，应以当前拨号设备的配置为准。
