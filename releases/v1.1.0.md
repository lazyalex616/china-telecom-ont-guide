**这次公开两台已授权光猫连上 SSH 的完整方法：合法临时维护通道 → 已存在的 SAF 应用环境 → 自编译 Dropbear → 密钥登录 → 独立内网入口。没有刷固件，也没有永久开启 Telnet。**

## 新增第 12 章：SSH 是怎样连上的

[阅读完整章节](https://github.com/lazyalex616/china-telecom-ont-guide/blob/v1.1.0/docs/12-native-app-ssh.md)

1. 已有有效超密，通过符合当前固件的合法临时维护通道取得安装权限。
2. 进入光猫原生 SAF 应用环境，不改主系统固件或应用管理器。
3. 从上游编译 Dropbear 2026.94，分别生成 ARM64 和 MIPS 小端程序，核对完整性后安装。
4. 客户端私钥留在管理端，只传公钥；每台生成独立主机身份，禁用密码和转发。
5. 路由器提供各站点独立内网入口，同时处理去程和回程，避免两台管理地址相同而连错。
6. 核对主机身份后完成实际密钥登录，关闭本次临时 Telnet 和传输入口。

章节同时记录 Windows OpenSSH 9.5 的算法兼容现象、非默认端口 `known_hosts` 格式、BusyBox 命令差异、临时入口清理及应用与主系统的边界。

## 启动模板不是一键固化器

新增 [`tools/ont-ssh.init`](https://github.com/lazyalex616/china-telecom-ont-guide/blob/v1.1.0/tools/ont-ssh.init)：

- 只适用于已核实的 SAF 应用内 `rc.common` 启动机制，不自动部署。
- 监听地址默认是不可用占位符，必须自行核实并填写私有 IPv4，不回退到全地址监听。
- 禁止密码、空密码和 TCP 转发，公钥另行限制代理及 X11 转发。
- 管理地址未就绪时只有限重试自己的服务，停止时核对 PID 的执行程序。
- 不自动取得权限，不修改路由器，不重启光猫，不覆盖现有密钥或服务。

发行包**不包含 Dropbear 二进制、编译器、实际密钥、主机公钥或指纹、真实地址规划、私有连接注册表或一次性生产部署器**。Dropbear 各组件仍遵循上游完整许可，不因教程采用 MIT 而被重新许可。
